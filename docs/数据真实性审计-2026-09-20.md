## 三、② 数据是真的，却被标注成「示例数据」★★

| 位置 | 问题 |
|---|---|
| `pages/report/index.vue:72` | 客户销售额排行，副标题写「累计销售（**示例数据**）」 |
| `pages/report/index.vue:81` | 商品销售额排行，副标题写「按金额排序（**示例数据**）」 |

**但这两块实际调用的是真实接口**：

```js
reportApi.customerRanking({ limit: 5 })   // GET /reports/customer-ranking
reportApi.productRanking({ limit: 5 })    // GET /reports/product-ranking
```

**影响**：反向误导 —— 你会以为排行是假的，从而**低估了自己真实的客户/商品数据**。
建议把「（示例数据）」改成真实期间标注，如「本月累计」或「近 12 个月」。

## 四、③ 数据是假的、且无标注 —— 打印页（★ 高优先级）

### 症状

「我的 → 打印机」与「打印设置」页显示 **`0 台` / 未连接**，
但**这台机器实际有 2 台可用打印机**。

### 根因（我上次改动引入的回归）

线上真实响应：

```json
"capabilities": {
  "printers": {
    "hostName": "LAPTOP-G6JO41EG",
    "defaultPrinter": "Microsoft Print to PDF",
    "v3Printers": [
      {"hostName":"WISENB","printerName":"Microsoft Print to PDF","copies":0,"knife":false},
      {"hostName":"WISENB","printerName":"OneNote for Windows 10","copies":0,"knife":false}
    ]
  }
}
```

真实列表在 **`printers.v3Printers`**（2 条）。但 `print/index.vue:96-107` 写的是：

```js
const res = await capabilityApi.get()        // ← 已过 toCapabilities 适配
const data = res.data || {}
const agent = data.agent || data.agentCapabilities || {}   // ← 适配后 data.agent 已不存在
const pr = agent.printers || data.printers || {}           // ← data.printers 现在是【数字 2】
const list = pr.list || pr.items || data.printerList || [] // ← 对数字取属性 → 永远 []
printers.value = Array.isArray(list) ? list : []           // ← 永远 []
```

**实测复现**（用线上真实响应跑真实 `adapt.js`）：

| 表达式 | 实际值 |
|---|---|
| 适配后 `data.agent` | `None`（已拍平） |
| 适配后 `data.printers` | **`2`**（数字，不是对象） |
| `pr.list \|\| pr.items \|\| data.printerList` | `[]` |
| **`printers.value`** | **`[]`** → 页面显示 0 台 |

### 为什么会这样

我 2026-09-20 新增的 `toCapabilities()` **只保留了打印机数量 `printers: 2`，
丢掉了打印机名称列表**。而打印页是更早写的，还在按「对象 + list」的老形状读。
两边对不上 → 打印页永远空白。

### 修复方向（未实施）

给 `toCapabilities` 增补一个真实列表字段（如 `printerList`），
或让 print 页直接读 `caps.printerItems`。

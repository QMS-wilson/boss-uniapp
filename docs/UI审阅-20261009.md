## 结论先行

设计体系（令牌、动效、栅格）是这份代码里最扎实的部分。问题不在"没有规范"，而在
**规范之外还有一批没被收编的值**，加上几处语义色用反了。真正影响每天使用的只有 5 条：

1. **小字配弱色** —— `$color-text-4(#9aa5b3)` 在页底上只有 **2.31:1**（WCAG AA 要 4.5），
   却用在单据日期、对账流水号、逐笔余额上；同时全站 11~12px 的小字有 **245 处**。
2. **同一个"单价"两种颜色** —— 商品列表是蓝、商品详情是红，详情页一屏 4 个红值。
3. **"金额"没有统一定义** —— `AmountText` 无条件默认红，导致销售明细金额、销售/采购
   「合计」全红（含 `0.00`），而销售单**列表**行金额是深色。
4. **悬浮「+」压住列表最后 1~2 行的右侧**（价格/库存列），列表尾部只留了 30px。
5. **对账页日期列 54px 装不下 66px 的日期**，`2026-09-05` 断成两行。

## P0 详情

### U1 小字配弱色，最低对比度 2.31:1

实测（WCAG 相对亮度公式实算，非估值）：

| 前景色 | 页面底 #f5f6f8 | 卡片白 #fff | 凹陷底 #eef1f5 |
|---|---:|---:|---:|
| `$color-text` #202b3b | 13.21 ✓ | 14.28 ✓ | 12.61 ✓ |
| `$color-text-2` #536175 | 5.82 ✓ | 6.30 ✓ | 5.56 ✓ |
| `$color-text-3` #8995a5 | **2.81 ✗** | 3.04（仅够大字） | **2.68 ✗** |
| `$color-text-4` #9aa5b3 | **2.31 ✗** | **2.50 ✗** | **2.20 ✗** |
| `$color-warning` #e8952f | **2.21 ✗** | **2.39 ✗** | **2.11 ✗** |
| `$color-success` #27a866 | **2.82 ✗** | 3.05（仅够大字） | **2.69 ✗** |

问题不是"用了浅色"，而是浅色用在了**要读的值**上：

- `components/BillRow.vue:82` `.bill-row__date` → `$color-text-4`：单据列表里的**日期**
- `pages/report/reconcile.vue:352-370` `.ledger__no`（流水号）、`.ledger__balance`（逐笔结余）→ `$color-text-4`
- `pages/product/list.vue:76` `.prod-row__fold`（`≈ 12个` 换算）→ `$color-text-4`

叠加字号：`$fs-caption`(13px) 131 处 + `$fs-mini`(12px) 157 处 + `$fs-micro`(11px) 88 处 = **245 处小字**。

**建议**：把"要读的值"提到 `$color-text-2`（5.82:1）；`$color-text-4` 只留给真正的
placeholder 与纯装饰。想保留四级层次就把 `text-4` 加深到约 `#7b8798`（3.7:1）。

### U2 同一个「单价」，列表蓝、详情红

- 列表：`pages/product/list.vue` `.prod-row__amount{ color:$color-primary }`
- 详情：`pages/product/detail.vue:266` `.units__money text:first-child{ color:$color-danger }`

红色在本系统的既定语义是「应收/支出/危险」，用在售价上语义不对；且同一货品从列表点进
详情颜色会跳变。

**建议**：详情四个价格统一 —— 默认销价用主色，进价/成本价用深色或 `$color-text-2`；
红色只留给有方向的量（应收/应付/亏损）。

### U3 「金额」没有统一定义

`components/AmountText.vue:26` 是无条件红：

```scss
.amount { color: $color-danger; }
.amount.neg { color: $color-success; }  /* 负数才转绿 */
```

使用方：`sales/edit.vue:137,226`（行金额 + 合计）、`purchase/edit.vue:117,161`（同）、
`customer/list.vue:50` / `supplier/list.vue:46`（应收应付，这两处红是**对的**）。

但销售单**列表**行金额是深色：`components/BillRow.vue:87` `color:$color-text`。

**建议**：定成明文规则并只在一处实现 —— 应收/应付→红、收款/退款→绿、金额与合计→深色。
去掉 `AmountText` 的默认红，改由调用方显式传 `tone`。

### U4 FAB 遮挡列表最后 1~2 行

几何（可直接算出）：

- `App.vue:583-598` `.fab{ bottom: calc(#{$tabbar-height} + 40rpx + safe); height:112rpx }`
  ⇒ 占用距底 **75~131px** 的条带，右侧宽 **56+18=74px**
- `App.vue:532` `.bottom-gap{ height:60rpx }` = **30px**
- 30px < 131px ⇒ 列表尾部 **101px** 落在 FAB 覆盖区内；截图实测 `¥5.00/条`、`库存 0条` 被压住

**建议**：`.bottom-gap` 改 `calc(#{$fab-size} + 60rpx)`（≈156px），或给列表加
`padding-right: $fab-size`（后者更省纵向空间）。

### U5 对账页日期列 54px < 内容 66px

- `pages/report/reconcile.vue:356` `.ledger__date{ flex:0 0 auto; width:108rpx }` = 54px
- 同处 `font-size:$fs-mini`(12px) + `$font-num`（Outfit 等宽数字 ≈0.55em）
  ⇒ `2026-09-05` 10 字符 ≈ **66px > 54px** ⇒ 必然折行
- 同一套样式被导出弹层复用，两处都断

**建议**：width 提到 `132rpx` + `white-space:nowrap`；或日期只显示 `09-05`（同屏已有期间范围）。

### U7 开单页一行商品叠 6 个信息块
> ⚠️ **本条的建议已修正三次，以本节 + 文末「追加 · U7 重排」为准。**

一行自上而下：品名 + 单位胶囊 → 规格 → 库存/折合/取价条（`history-toggle`，实际会折成 2 行）→
数量/单价/金额 → 备注输入（`.item-remark`）。实测一行卡片 **240.5px**（卡片内宽 303px，可用 279px）。

**建议（按用户三条指令重排后的最终版）**：
1. **规格上移品名行** —— `<text class="it-spec">12*2 · 按个开</text>` 从独立的 `.it-spec-row`
   挪进 `.item-top`，跟品名同一行。**整行消失，省 36px**（`margin: 10rpx 0 18rpx` = 5+9px
   + 行高 22px），每行都省、零交互依赖。
   ★ 必须同时给 `.it-name` 加 `max-width:52%` + `text-overflow:ellipsis`，
   否则长品名时品名与规格互挤、**双双截断**（见下）。
2. **赠品从规格行挪到「备注」行** —— ✅ 用户先提"聚合到数量/单价/金额那一行"，
   后来**自己指出这样会挤**：「数量多些或者单价大些都会显示不完整」。
   **实测完全成立**（见下节），所以落点改到宽度最宽裕的备注行：`备注 [输入框] [🏷 赠品]`。
3. **备注保持常驻，一个字都不动。** ✅ 用户否决了"空态折叠成 `＋ 备注`"的方案 —— 见文末说明。
4. **「取价 / 最近销售」收进「单价 ▾」**（可选，独立一项）—— 再省 **17px**，代价是多点一层。

**★ 赠品为什么不能放「数量/单价/金额」那一行**（用户异议 → 实测确认）：

赠品胶囊实测宽 **54px**。它挤进那一行后，两个 `flex:1` 输入框从 91px → 61.5px，
即使按我上一版建议把数量列固定 56px、列间距压到 6px，单价框也只回到 **76px（可用 56px）**：

| 字段 | 可用宽 | 输入值 | 需要 | 结果 |
|---|---:|---|---:|---|
| 数量（框 56px） | 36px | `1234` | 32.2px | OK |
| | | `12345`（5 位） | 40.3px | **溢出** |
| | | `123456`（6 位） | 48.3px | **溢出** |
| 单价（框 76px） | 56px | `156.00` | 44.1px | OK（**我上一版只验到这一档**） |
| | | `1560.00` | 52.1px | 仅剩 3.9px |
| | | `12345.00`（5 位整数） | 60.2px | **溢出** |
| | | `156000.00`（6 位整数） | 68.2px | **溢出** |

**单价 5 位整数（设备、材料单价上万很常见）就溢出。** 我上一版算的 +11.9px 余量只覆盖到
`1560.00`，往上一档就崩 —— **这是我把"够了"当结论的检查漏洞：只验了一个样本值，没做压力测试。**

**三个落点实测对比**（同一张卡片，内宽 279px）：

| 落点 | 数量框 | 单价框 | 单价可用 | 备注框可用 | 行高 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| 数量行（我上一版） | 56px | 76px | **56px** | 233px | 204.5px | ✗ 单价 5 位整数溢出 |
| **备注行（推荐）** | 64px | 128px | **110px** | 167px | 204.5px | ✓ 宽度翻一倍，`156000.00` 也放得下 |
| 取价/最近销售行 | 64px | 128px | 110px | 233px | 204.5px | △ 宽度够，但两坑（见下） |
| 品名行 | — | — | — | — | — | ✗ 赠品会紧贴 `✕`，又回到"误触删除"风险 |

**为什么推荐备注行**：① 单价可用宽 56px → **110px**，彻底解掉显示不全的问题；
② 备注行没有整行 `@click`，**不动任何已有交互区**；③ 语义可比（都是"这一行的补充标记"）；
④ 零高度代价（204.5px 不变）。
**配套两处**：`gap` 从 `12rpx` 提到 **`16rpx`**（免得赠品被看成备注输入框的一部分）；
数量列固定 **64px**（不是 56px）—— 空间够了，让它放得下 5 位。

**★ 赠品为什么不放「取价/最近销售」行**（用户问的另一个落点）：
宽度也够（`.ht-left` 可用 257px），行高也不涨（那一条本来就折 2 行，加赠品仍 2 行），但：
1. `.history-toggle` **整行是 `@click="toggleHistory"` 的点击区**，塞进去必须 `@click.stop`；
   漏了就会"点赠品顺便把历史面板展开/收起"，且**只在点赠品时出现**，很难被发现。
2. 那一条全是**只读系统提示**（折合 / 库存 / 取价 / 最近销售），塞一个**可写开关**进去，
   用户会分不清"这一行到底能不能点"。
3. 赠品放外层后 `.ht-left` 可用宽从 **257px 掉到 203px** —— 本来就折 2 行的一行，
   在「长货品名 + 长库存提示」时更容易折成 3 行，**高度反而会涨**。

**★ 取舍要说清**：源码 116 行注释写着「赠品：点一下这一行就不计入合计」——
赠品是**影响金额的开关**，语义上最贴"数量/单价/金额"那一行。**用户的直觉是对的**，
是宽度不允许才退到备注行 —— **备注行是"语义次优、工程最优"的落点**。

5. **品名/规格"点开看全文"**（可选，见下节）—— 解决"规格上移后两个都被截断"的代价，实现很轻。

**⑤ 品名/规格的展开与收起（用户问："点哪个就展开哪个，再点一次收缩"）**

**能做，而且不用新增任何资源**：`chevron-down` / `chevron-up` 图标项目已有（`BarChart.vue:37,41`），
展开先例 `toggleHistory` 也在。一个布尔量 + `v-if`，跨端零兼容问题。

**★ 但建议改一点：不要"点哪个展开哪个"，合并成一个开关。**
这一行是**单行布局**，品名与规格共享同一条 193.6px 宽。所以：

- 点品名 → 品名要折行显示全文，**规格必然被挤到第二行**
- 点规格 → **同样被挤到第二行**
- ⇒ **两条路的落点都是"变成两行"**，差别只在"谁留在第一行"

而两个独立开关会带来两个真问题：
1. **按钮位置会跳**：点品名展开后规格跑到第二行，规格的 `▾` 也跟着跑 —— 用户想再点规格得去别处找。
2. **状态组合要定义**：两个都展开算哪种？展开顺序不同会不会长得不一样？
   **用户其实只想"看全文"，不关心谁先谁后。**

**建议：点"品名 + 规格 + ▾"整块 → 一次把两个都展开；再点整块收回。**

**实测三态**（同卡片，可用内宽 279px）：

| 状态 | 卡高 | 品名宽 | 品名 | 规格宽 | 规格 |
|---|---:|---:|---|---:|---|
| 收起（短名 `防水胶圈`） | 204.5px | 56px | 完整 | 69.6px | 完整 |
| 收起（长名，默认态） | 187.5px | 100.6px | **截断** | 62.9px | **截断** |
| **展开（点一下）** | **219.5px** | **171.6px** | **完整（可折 3 行）** | 整行 | **完整** |
| 展开（极长名 24 字） | — | 171.6px | 折 3 行后收（`line-clamp:3`） | 整行 | 完整 |

**展开 +32px，再点收回 −32px。**
★ 注意是 **32px 不是 36px** —— 赠品挪去备注行之后，规格行不再有 22px 高的赠品胶囊撑着，
行高由 12px 规格文字（18px）决定 ⇒ `margin 5+9px + 行高 18px = 32px`。

**★ 实现要点：用页面级一个 `ref`，不要往 `it` 上加字段。**

```js
const openDescLine = ref(null)   // null = 全收起
function toggleDesc(i) { openDescLine.value = openDescLine.value === i ? null : i }
```

理由：
1. **不用动 5 处初始化。** `showHistory` 这样的字段要在 `createItem` 的 4 处
   （`sales/edit.vue:981 / 1156 / 1303 / 1324`）+ `utils/adapt.js:174` 各写一遍
   —— **漏一处就会在那条路径下静默失效**（新建行 / 复制行 / 改单回填 / 适配层四选一），
   表现是"点了没反应"，而不会报错。这正是项目踩过的"字段名对不上只静默变 0"同类坑。
2. **天然互斥**：一次只展开一行，不会"连点五行、五行全展开把屏幕撑爆"。
3. **状态不会被冲掉**：表单重渲染、`JSON` 克隆、改数量触发 `recalc` 都不影响它。

展开态复用**现有的 `.it-spec-row` 结构**（`v-if` 挂回），所以展开后 = 用户熟悉的老两行布局。

**四条必须一起处理的限制**：

1. **`▾` 必须"一直显示"，做不出"只有被截断才显示"。**
   小程序**逻辑层没有 DOM**，拿不到 `scrollWidth / clientWidth`；canvas `measureText` 在小程序里
   要先有真 canvas 实例、且字体度量与渲染不一致（本项目已测过 CJK 字宽差异）。
   ⇒ **判断不了"是否截断"**，一律靠 `…`（`ellipsis` 自带）+ `▾` 双提示。
2. **触点与相邻可点对象不冲突 —— 这点天然成立。** 热区只包 `.it-name-line`，
   而 `.it-units`（切单位）和 `.it-del`（删行）是 `.item-top` 的**直接子元素、在热区之外**
   ⇒ **不需要 `@click.stop`**。这也是为什么**不要把热区做成整个 `.item-top`**。
3. **行距断言要跑在收起态。** 项目有校验脚本量相邻卡片 `rect.top − 上一张.bottom = 0`，
   展开态会破坏它 ⇒ 断言必须在点击之前跑（默认就是收起态）。
4. **展开会把下方卡片顶下去。** +32px 只发生在用户主动点的时候，可接受；
   但**别做成"默认展开"**，那就等于回到原来的高度。

**备选 D2（零新增交互）**：品名行完全不可点，把**完整品名 + 完整规格 + 取价**一起收进
「单价 ▾」面板 —— 那个面板的语义本来就是"这一行的详细信息"，`›` 指示也已经在。
零误触、零高度影响、零新字段；代价是**多点一层 + 要滚动**。

**高度账**（备注全程常驻，`getBoundingClientRect()` 实测）：

| 方案 | 内容 | 行高 | 相对现状 |
|---|---|---:|---|
| 现状 | 规格独占一行 + 赠品挤在规格行 + 取价折 2 行 | **240.5px** | — |
| 纯重排（①②③） | 规格上移 · 赠品挪到备注行 · 备注常驻 | **204.5px** | **−36.0px（−15.0%）** |

## U7 重排：用户的三条指令与实测结果

**用户原话**：「建议还是常驻好些，放删除按钮旁边容易误点到删除。可以把第二行的规格按个开那个放在

### ① 备注改回常驻 ✅（用户否决，理由成立）

上一版我建议"备注空态折叠成行首 `＋ 备注`"，位置放在 `.item-top` 的 `✕` 左边。
**用户否决理由：放删除按钮旁边容易误点到删除。**

这条我完全没想到。`＋ 备注` 和 `✕` **都是行级操作**，贴在一起时：
- 点错备注 → 多开一个输入框，退掉就行，**代价≈0**
- 点错 `✕` → **整行商品被删掉**，要重新选货品、重新填数量单价，**代价≥30 秒**

**用"省 38.5px"去换一个"可能误删整行"的风险，不划算。** 备注恢复常驻，位置不动。
（真正省高度的地方改押在 ② —— 规格行消失，**每一行都省、且不依赖任何交互**，比押在备注上稳得多。）

### ② 规格上移品名行 ✅（可行，但必须配 max-width）

`<text class="it-spec">12*2 · 按个开</text>` 从独立 `.it-spec-row` 挪进 `.item-top`。
**删除 `.it-spec-row` 整行 ⇒ 省 36px**（`margin:10rpx 0 18rpx` = 5+9px + 行高 22px）。

**★ 代价：长品名时品名与规格互挤。** 实测那条 `日本东发（蓝弹）日本东发` +
`18*85 · 按条开`：给 `.it-name` 加 `max-width:60%` 后，
- 品名被截成 `日本东发（蓝弹…`（实测宽 116.1px，`scrollWidth > clientWidth` 成立）
- **同时规格也被截成 `18*85 · 按…`（69.4px，同样溢出）** —— 两个都变残

**做法**：`.it-name{ max-width:52%; text-overflow:ellipsis }`（给规格留位）+
`.it-spec{ ellipsis }`；规格只显示 `·` 前的部分（`12*2`），完整规格留给 `▾` 面板或详情页。

### ③ 赠品离开规格行 → 落点从「数量行」改到「备注行」⚠️→✅

**用户先提**「赠品按钮聚合到数量单价金额那一行看看」，**然后自己推翻**：
「赠品放在数量行可能不好，数量多些或者单价大些都会显示不完整」。

**实测：用户对。** 赠品胶囊 54px 挤进那一行后（即使按我上一版建议把数量列固定 56px、间距压到 6px）：

| 字段 | 可用宽 | `1234` / `156.00` | `12345` / `12345.00` | `123456` / `156000.00` |
|---|---:|---|---|---|
| 数量（框 56px） | 36px | 32.2px OK | **40.3px 溢出** | **48.3px 溢出** |
| 单价（框 76px） | 56px | 44.1px OK | **60.2px 溢出** | **68.2px 溢出** |

**单价 5 位整数就溢出**（`1560.00` 只剩 3.9px 余量）。**我上一版只验了 `156.00` 就下"够了"的结论
—— 没有做压力测试，这是检查漏洞。**

**五个落点实测**（同卡片，内宽 279px）：

| 落点 | 数量框 | 单价框 | 单价可用 | 备注框可用 | 行高 | 结论 |
|---|---:|---:|---:|---:|---:|---|
| m0 现状（赠品在规格行） | 91px | 91px | 71px | 233px | 240.5px | 宽度安全，但规格行白占 36px |
| m1 只照用户原话（赠品在数量行） | 61.5px | 61.5px | 41px | 233px | 204.5px | 单价 7 字符即溢出 |
| m4 = m1 + 数量固定 56 + 间距 6 | 56px | 76px | 56px | 233px | 204.5px | 单价 5 位整数仍溢出 |

**为什么最终落「备注行」**：① 单价可用宽 **56px → 110px**（`156000.00` 也放得下）；
② 备注行**没有整行 `@click`**，不动任何已有交互区；③ 语义可比（都是"这一行的补充标记"）；
④ 零高度代价。**配套**：`.item-remark` 的 `gap` 12rpx → **16rpx**；
数量列固定 **64px**（空间够了，放得下 5 位）。

**为什么落「取价行」不行**（用户问的另一个落点，宽度/高度其实都满足）：
1. `.history-toggle` **整行是 `@click="toggleHistory"` 的点击区** ⇒ 赠品必须 `@click.stop`，
   漏了就会"点赠品顺便展开/收起历史面板"，且**只在点赠品时出现**，极难发现；
2. 那一条全是**只读系统提示**（折合/库存/取价/最近销售），塞**可写开关**进去，用户分不清能不能点；
3. 赠品放外层后 `.ht-left` 可用宽 **257px → 203px**，本来就折 2 行的一行在长文案下更容易折 3 行，**高度反而会涨**。

**★ 取舍要写进方案**：源码 116 行注释「赠品：点一下这一行就不计入合计」——
赠品是**影响金额的开关**，语义上最贴"数量/单价/金额"那一行。**用户的直觉是对的**，
是宽度不允许才退 —— **备注行是"语义次优、工程最优"的落点**。

## 度量方法学（做对比板时的教训）

- **别用估算值写结论。** 上面三条都是"我以为"被浏览器量出来的数字推翻的。
  凡是要写进报告的数字（高度、宽度、行数），一律 `getBoundingClientRect()` 量一遍。
- ★★ **"量了一个样本"不等于"量过了"。** U7 的赠品落点我第一版只拿 `156.00` 验证，
  算出余量 +11.9px 就下"够了"的结论 —— 用户用一句"数量多些或者单价大些都会显示不完整"
  就指出了漏洞。**凡是要判断"会不会挤/会不会溢出"，必须做边界压力测试**：
  把字段按其业务上限取值（数量 6 位、单价 6 位整数）逐个量 `measureText()` 宽度。
  只用单个样本值验宽度，等于没验。
- **对比面板必须"只改一处"**，且两侧的其它元素要一致（U7 第一版漏了备注行，
  差点把降幅写成 40%）。
- ★ **对比板里的"精确复现"要带描边补偿。** `.phone` 自身有 1px 描边 ×2，
  起手用 327px 复现 303px 内宽时少了 2px（实测 92 vs 91）；改成 **329px** 才对得上。
  **复现完必须回量一遍**，不能凭算式断定。
- ★★ **新增状态字段前，先问"能不能不加字段"。**
  `it.showHistory` 这种字段要在 `createItem` 的 **4 处**（`sales/edit.vue:981/1156/1303/1324`）
  + `utils/adapt.js:174` 各初始化一遍 —— **漏一处就在那条路径（新建/复制/改单回填/适配层）下静默失效**，
  表现是"点了没反应"而**不报错**。U7-d 的展开态改用**页面级一个 `ref`** ⇒ 零初始化点、
  天然互斥（一次只展开一行）、表单重渲染不会冲掉。**能提升到页面级就别塞进行对象。**
- ★ **"点哪个就展开哪个"在单行布局里会退化成"展开成两行"。** 两个元素共享一条宽度时，
  任一元素要显示全文都会把另一个挤到下一行 ⇒ 两个独立开关的结果相同，只是**按钮位置会跳动**、
  状态组合要额外定义。**遇到这类需求先问：用户要的是"分别展开"还是"看全文"？**
  后者只需要一个开关。
- **复现不是 1:1 稿件。** 字体 CJK 字宽与真机有几个百分点差异 ⇒ 用于判断
  "会不会挤/会不会折/对比够不够"可靠，不能当像素级稿；这一条已写进对比板页脚。
- ★★ **`node script.js | head -3` 会 SIGPIPE 杀掉脚本**，导致逐块截图只出了前 4 张、
  后面 6 张静默保留旧文件（本次踩到，靠文件 mtime 才发现）。批量出图要重定向到文件再 `tail`。

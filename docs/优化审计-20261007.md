## 一、真缺陷（代码可证，影响可用性）

### 1. 「我的 → 打印机」是死入口：进去后预览/打印按钮永远灰的
- `src/pages/my/index.vue:159`：`function goPrint() { uni.navigateTo({ url: '/pages/print/index' }) }` —— **不带 `billId`**。
- `src/pages/print/index.vue:130`：`const canPrint = computed(() => !!billId.value && !printing.value)`；`:188` `onLoad((q) => { billId.value = q.billId || '' ... })`。
- 后果：从「我的」进来 `billId=''` ⇒ `canPrint=false`，「打印」按钮 `:86` 带 `is-disabled`、`:163 if (!canPrint.value) return`；「预览」`:83` 同样 `:disabled : !billId`。**整页只能看，什么都做不了**。
- 修法（选一）：① 带最近一张单进去（`bill.list?limit=1`）；② 把这一行改成只读的设备/打印机信息页；③ 撤掉该行入口。别留成假入口。

### 2. 采购单：只能看 —— 改单、打印均无后端能力，但界面入口还在
- `src/api/purchase.js:106`：`update: () => Promise.resolve(notImplemented('修改采购单'))`；`:113` 文案自认「Agent 侧只实现了 purchase.create」。
- `src/pages/purchase/detail.vue:163`：`uni.showToast({ title: '采购单打印后端暂未开放' })`。
- Agent 侧实证 `进销存-本地Agent源码/v3agent/ops.py`：`salesbill.*` 有 `update/audit/unaudit/void/copy` 六个，`purchase.*` 只有 `list / get / create` 三个 ⇒ **确认是后端缺口，不是前端漏接**。
- 现状处理是诚实的（`purchase/detail.vue:172`、`purchase/edit.vue:743` 都如实说明），但采购链路仍只走通「新建」一半。要闭环需 Agent 补 `purchase.update` + 打印 op，再排改单/打印前端。

### 3. `LineChart` 有一个不清理的定时器
- `src/components/LineChart.vue:317`：`onMounted(() => { nextTick(...); setTimeout(measure, 260) })`。
- 全文 grep **无 `onUnmounted` / `onBeforeUnmount`**（组件里其它定时器也没有集中清理）。
- 后果：图表组件卸载后 260ms 回调仍会跑 `measure()`；页面已销毁时读容器几何是无意义调用，长会话内反复进出报表页会累积。属低危但真实的泄漏。
- 修法：`const t = setTimeout(measure, 260)` + `onUnmounted(() => clearTimeout(t))`。

## 二、一致性缺口（同一件事两套做法）

### 4. 列表搜索：单据列表要按回车，档案列表边打边搜
| 页面 | 触发方式 | 证据 |
|---|---|---|
| 销售列表 | **仅 `@confirm`** | `sales/list.vue:12` `@confirm="reload"`，无 `@input` |
| 采购列表 | **仅 `@confirm`** | `purchase/index.vue:11` 同上 |
| 客户/商品/供应商/库存 | `@input` + debounce 350ms | `customer/list.vue:107` `const onInput = debounce(reload, 350)`；`product/list.vue:142`、`supplier/list.vue:105`、`inventory/index.vue:164` 同款 |

- 后果：单据列表打字后**不回车＝列表纹丝不动**，是「搜了没反应」的常见误报来源；而档案列表行为相反。两套手感在同一 App 里并存。
- 修法：单据列表也接 `debounce(reload, 350)`（`utils/format.js` 已有 `debounce`），并保留 `@confirm` 立即触发。★ 注意 `sales/list.vue` 的 `fetch()` 已有 `seq` 代际守卫（`:303` `const my = ++seq`），加防抖不会引入新竞态。

### 5. 首页入口不全，高频动作缺位
- `home/index.vue:73-76`：底部只有**一颗** `新建销售单`。
- `:80-100`：三入口 = 客户资料 / 产品资料 / 供应商资料 —— **没有「库存」**（老板看库存频率高于看供应商资料，现在要绕「我的 → 库存」`my/index.vue:158`）。
- `:118-128` 最近销售单每行只 `goDetail`（`:237`），**没有「再来一单」** —— 而复制模式早已存在（`sales/edit.vue` 认 `mode=copy&from=<单号>`），**零后端成本**。

### 6. 登录页不记住上次操作员
- 全站用户偏好键只有 6 个：`cfg:stockWarn` / `cfg:billStockWarn` / `cfg:draftTtlDays` / `cfg:billZeroGift` / `cfg:billExitAsk` / `cfg:agentNotice`（grep `cfg:` 全站统计）。
- `login/index.vue` **没有任何 `cfg:` 键**，`operator` 每次都从零开始（清单多时要翻）。
- 修法：登录成功写 `cfg:lastOp:<商户码>:<账套>`（**必须带商户码+账套后缀**，与草稿分桶同理），下次预选/预填；不预填口令。

## 三、工程 / 性能

### 7. 无分包：29 个页面全在主包
- `src/pages.json`：解析后 `subPackages = 0`、`pages = 29`。
- 现状小程序产物约 0.62 MB（离微信主包 2 MB 还有余量），但**功能是线性往主包加的**（历史：赠品/停用标签/筛选半屏都进主包）。建议给报表/打印/供货商这几簇拆 `subPackages`，把增长挡在主包之外。

### 8. 无 `manualChunks`，首屏 chunk 308 KB
- `vite.config.js` 无 `rollupOptions`/`manualChunks`/`chunkSizeWarningLimit`。
- 产物实测（`dist/build/h5/assets/`）：`index-*.js` **308K**、`Icon.*.js` 40K、`pages-report-index.*.js` 40K。
- `Icon.vue` 源 42.8 KB / 91 处 data-URI（图标 + 配色组合全内联）。它被 33 个文件引用，**每页都要带上**。可考虑按 tabBar/页面分组拆或改「少量常用 + 按需」，收益中等。

### 9. 请求层只有「取消表」，没有全局并发闸
- `src/utils/request.js`：`_inflight`（`:53`）语义是**同 `flightKey` 后发顶掉并发前一条**（`:205-214`），不是"共享同一结果"；全文无并发上限/信号量/队列。
- 后果：首页 `onShow` 一次会同时发多块（本月/今日/应收/待办/最近单），弱网时把云端在途位一起占满；`cloudapi` 侧对 report 有闸，但普通 GET 没有。
- 修法：加一个轻量并发上限（如 GET 最多 6 路，超出排队），或在 `request()` 入队时按 scope 限流。

### 10. 死文件 / 备份残留（不进产物，但污染源码树）
- `src/components/Icon.vue.bak-svg`（7.5 KB，Sep 21）
- `src/components/GridEntry.vue.retired-20261004`
- `scripts/deploy.py.bak-flat-20260925`
- 风险：图标生成器（`scripts/gen-icon-data.py`）与一次性脚本是**扫源码**的，残留的旧 `Icon.vue` 变体会被扫进组合表/造成误判（历史上已因手写组合表漏 21 组踩过坑）。建议移到仓库外归档目录。

### 11. `src/mock/`（44 KB）源码树里仍是一整套示例数据；**小程序包会把它带进去**
- `utils/config.js:156` `USE_MOCK: false`；`utils/request.js:13` 仍然静态 `import { mockRequest }`。
- **H5 产物**：`dist/build/h5/assets/*.js` 里搜 `示例数据 / mockRequest` **0 命中** ⇒ 已摇掉，不占体积。
- ★ **小程序产物不是这样**（2026-10-07 构建后实测）：`dist/build/mp-weixin/mock/` 带着 `data.js`（9.5 KB）+ `router.js`，
  目录 13 KB。原因是 `mock/router.js`（源 415 行）被摇成只剩一句：
  ```js
  "use strict";require("./data.js");
  ```
  逻辑摇掉了，但这句 **side-effect import 把 `data.js` 拖了进来**，且包内无人引用它。
- 修法：`src/mock` 目录加 `"sideEffects": false`（或在 `package.json` 里声明），或干脆删掉这一套。
  代价很小（13 KB），但它是"照 mock 形状写页面"那类旧坑的温床（历史事故：`capabilities` 按 mock 的平铺字段写，接真机全错）。

### 12. 报表两个下钻页显式拉全量客户，无上限保护
- `report/goods.vue:277`、`report/reconcile.vue:280`：`customerApi.list({ pageSize: 1000, showStopped: true })`。
- 当前 126 户够用，但**写死 1000 且无截断提示**（现有 `custTotal` 说明是后补的）；客户上千后静默少人。
